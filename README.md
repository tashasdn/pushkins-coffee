# PUSHKINS COFFEE

[Сайт PUSHKINS COFFEE](https://pushkins-coffee.pages.dev/) · [Telegram-бот @pushkinscoffeeebot](https://t.me/pushkinscoffeeebot)

Меню авто-кофейни и форма обратной связи. Форма сохраняет черновик, а личная ссылка открывает Telegram для подтверждения. Бот показывает статус и историю.

Сайт развёрнут на Cloudflare Pages Free в проекте `pushkins-coffee`. В отдельном [проекте Supabase Free](https://supabase.com/dashboard/project/wtuoiimwikxeuzipwvjz) применены обе миграции. В базе проверены RLS на пяти таблицах, закрытый доступ к шести RPC и отсутствие заявок перед запуском. Telegram подтвердил webhook и доставку служебного сообщения в личный чат владельца. Проверка полного пути обращения выполняется отдельно.

## Работа в Telegram

- `/requests` — список для владельца. Фильтры «Новые», «В работе», «Все». В карточке доступны ответ, история и смена статуса.
- `/my` — собственные обращения и история заявителя. «Написать уточнение» открывает подсказку для ответа.
- `/id` — ID отправителя в личном чате. `/retry` — ошибки доставки для владельца и повтор выбранной отправки.
- На подсказку «Ответьте на это сообщение» нужно ответить средствами Telegram. Каждая подсказка связана с конкретным обращением.

## Проверка и обновление

Для разработки нужен Node.js 22 или новее. Для работы опубликованного сайта и бота компьютер владельца может быть выключен.

```sh
npm ci
npm run check
npm test
npm run preview
npm run bundle
```

Тесты выполняют обе SQL-миграции в PGlite и используют отдельный тестовый Telegram-транспорт. Preview открывает страницу под `/pushkins-coffee/`. Для публикации загружается только каталог `public/`. В нём `config.js` хранит только URL функции формы и публичное имя бота.

Чтобы обновить сайт, загрузите ZIP с содержимым `public/` через **Create deployment** в проекте Cloudflare Pages. Сайт использует Direct Upload. GitHub хранит исходники и запускает проверки. Рабочая версия размещена на согласованной площадке Cloudflare Pages Free из-за ограничений GitHub Pages для ведения бизнеса. Workflow GitHub Pages оставлен ручным и выключен. [Правила GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

### Подключение и обновление сервера

1. В отдельном проекте Supabase Free применить SQL-миграции из `supabase/migrations/` по порядку. После первого запуска изменения базы вносить новыми миграциями. Схему `requests_app` не добавлять в Exposed schemas. Для RPC нужна Data API и стандартная схема `public`.
2. Скопировать настройки из игнорируемого `.local/secrets.env` в Edge Functions Secrets. `SITE_URL` — полный HTTPS-адрес сайта. Источник CORS вычисляется из него. Ключ базы берётся из серверных переменных Supabase.
3. Опубликовать три функции из исходников CLI или из отдельных файлов `.local/dashboard/*.ts`, созданных командой bundle. JWT gateway отключить только для этих функций. Форма открыта для посетителей с ограничением частоты, webhook и настройка проверяют собственные секретные заголовки.
4. Вызвать `node scripts/setup.mjs register <project-ref>`, затем `status`. Все вызовы Telegram при настройке выполняет Supabase. Скрипт `owner.mjs` — разовая проверка до webhook при доступном Telegram API. При отсутствии доступа отправить `/id` боту в личном чате после регистрации и установить `ADMIN_CHAT_ID` по полученному ID. Выполнить действие `test` и получить проверочное сообщение. С действующим webhook `getUpdates` не используется.
5. После проверки удалить только развёрнутую `setup-telegram`, сохранив исходник. Указать действующие URL и имя бота в `public/config.js` и опубликовать сайт. Изменение GitHub не обновляет Edge Functions или миграции автоматически. При обновлении функций использовать тот же проект и хранить действующие секреты.
6. Для живой приёмки провести одно помеченное контрольное обращение. Сверить номер, карточку владельца, ответ на ForceReply, историю, уточнение, статус и состояния outbox. Проверить, что webhook отклоняет запрос без секрета, а функция настройки недоступна. Отдельно проверить двух реальных заявителей и работу с телефона при выключенном компьютере, если доступны нужные аккаунты.

## Лимиты и восстановление

- Форма принимает до 10 новых черновиков с одного IP за 10 минут и 500 суммарно за последние сутки. Бот принимает до 30 действий в минуту с одного чата. Ссылка действует 30 минут. Неподтверждённые черновики старше суток могут удаляться при новых формах.
- База хранит историю подтверждённых заявок, обработанные события и очередь. Telegram принимает события через webhook. Задания возобновляются при повторах событий и новых действиях. При ошибке доставки используйте `/retry` после устранения причины. Если Telegram ограничил частоту, подождите перед повтором.
- После принятия сообщения Telegram функция фиксирует результат в базе. Авария между этими действиями может привести к повторной доставке. Отправитель сначала получает подтверждение сохранения, затем подтверждение доставки в чат.
- У Supabase Free ограничены ресурсы и вызовы. После низкой активности проект может приостановиться. Его можно восстановить из панели Supabase. Сохранность при удалении проекта зависит от ваших резервных копий. [Паузы проектов Free](https://supabase.com/docs/guides/platform/free-project-pausing)
